# research/ — ابزار پژوهش و بهینه‌سازی

ابزارهایی که با آن‌ها پارامترهای v2.2 کشف و اعتبارسنجی شدند.

## فایل‌ها

| فایل | توضیح |
|---|---|
| `ps_review.py` | موتور بک‌تست سریع درون‌حافظه‌ای + جست‌وجوی شبکه‌ای (همان معناشناسی موتور ربات: ورود بازِ کندل بعد، اولویت استاپ، گپ، BK، CM، کارمزد 0.2٪) |
| `final_set_v22.json` | پیکربندی نهایی قفل‌شده v2.2 |

## پنجره‌های استاندارد (تهران)

- **IS (بهینه‌سازی)**: `2026-07-10 → 2026-08-08`
- **OOS (اعتبارسنجی)**: `2026-08-09 → 2026-09-07`
- **کرش فوریه**: `2026-01-10 → 2026-02-15` (افت BTC 20.3٪)

## استفاده

```bash
# ۱) گرم‌کردن کش دیتای واقعی KuCoin (~2 دقیقه؛ فقط بار اول)
python research/ps_review.py fetch 2026-05-07 2026-09-08
python research/ps_review.py fetch 2026-01-05 2026-02-20   # برای تست کرش

# ۲) خط پایه پارامترهای فعلی scenarios.py
python research/ps_review.py baseline

# ۳) جست‌وجوی شبکه‌ای یک سناریو روی IS
python research/ps_review.py search F1

# ۴) ارزیابی یک ترکیب دلخواه
python research/ps_review.py combine '{"F1": {...}, "F3": {...}}'

# ۵) سویپ گیت رژیم / سقف ضرر روزانه
python research/ps_review.py gates
python research/ps_review.py portfolio

# ۶) جدول روزانه یک ترکیب
python research/ps_review.py daytable '<json>'
```

نکته: هر فرمان دیتا را از کش دیسکی (`data_review/` — گیت‌ایگنور) می‌خواند؛
کلیدهای کش روی مرز کندل گرد می‌شوند تا بین اجراها پایدار باشند.

## اصول

- اسپلیت IS/OOS **ورود-محور** گزارش می‌شود (خروج-محور برای معاملات بلند BK نشت دارد).
- هیچ پیکربندی با کمتر از 12 معامله (8 برای سناریوهای گیت‌دار) انتخاب نمی‌شود.
- برنده‌ها باید روی پلاتو باشند (همسایه‌های ±1 استپ هم مثبت)، نه knife-edge.
